# Security note: S8-8 — горячая перезагрузка detectors.yaml из UI

Дата: 2026-10-25
Изменение: форма «Детекторы» на /settings (admin-only) правит
detectors.yaml (пороги/веса/лимиты/proxy) с применением без рестарта.

## Поверхность и меры

| Вопрос | Мера |
|---|---|
| Кто может править | RBAC-действие manage — только admin (п. 11.3); dev-режим = субъект dev (тестовый контур) |
| CSRF | Классическая форма с csrf_token-полем (S8-6), POST-only |
| Утечка секретов | В detectors.yaml секретов нет по построению (только имена env api_key_env); аудит фиксирует значения порогов — допустимо (это не секреты) |
| Порча файла | Валидация до записи (строгий разбор + Detectors.Validate); .bak + атомарная замена; при неудаче apply — файл записан, процесс на старом конфиге, явное сообщение |
| Опасные правки | Реестр агентов и taxonomy через UI не редактируются (endpoint/egress/промпт-enum — рестарт, осознанное изменение); proxy.offline правится — но это ужесточение egress по умолчанию false, fail-closed сторона |
| Согласованность прогонов | Действующий прогон завершается со снимком порогов на старте (engine конфигурируется на старте) — нет частичного переключения внутри прогона |
| Промпт-дрейф (R6) | Правки не трогают промпты (prompts/ версионируются отдельно; реестр агентов read-only) — ворота R6 не затронуты |

## Принятые риски

- **Числа в файле нормализуются форматом** (1.0 → 1) — косметика, поведение
  идентично.
- **inline-комментарий редактируемой строки теряется** (общее свойство
  Node-правок, прецедент S8-7).
