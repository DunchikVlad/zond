# Security note: нагрузочный тест слоя 1 (инкремент 6г, п. 16.8)

Дата: 2026-10-24
Изменение: пакет `internal/benchlab`, подкоманда `cmd/eval bench`,
target `make bench`, шаг CI «Bench слоя 1 (NFR п. 18)».

## Поверхность изменения

- Новый код: `internal/benchlab` (генератор синтетики + прогон
  `rules.Analyze`), `cmd/eval bench`, wiring в Makefile/ci.yml/.gitignore.
- Новый генерируемый артефакт (в git не коммитится):
  `evals/reports/bench.json`.
- Сетевых вызовов нет во всех режимах; store/audit/секреты/SSO не
  затрагиваются (контур этапа 6, прецедент ADR-impl-6а D1).

## Меры (blueprint п. 14; fail-closed — ADR-security-llm-isolation)

| Угроза | Мера |
|---|---|
| Утечка PII через отчёт | Отчёт — только агрегаты (счётчики, throughput, NFR pass); значения синтетические (генератор детерминирован, seed известен), PII в контуре нет в принципе |
| Запись отчёта (`-out`) | `WriteReport` пишет один файл в заданный каталог (MkdirAll 0755, файл 0644), путей из данных нет; `-out ""` — без записи (форма CI) |
| Подмена результатов бенча | Генерация детерминирована (PCG, seed флагом); инварианты тестами: негативы не матчатся ничем, позитивы матчатся своим recognizer'ом на 100%, повторный прогон идентичен — подмена профиля видна в тестах |
| Негативы, случайно сматчившиеся (искажение профиля) | Генератор негативов построен на длинах/символах вне всех recognizer'ов (8–9 и 21–24 цифры, месяц 13, «user@nodomain»); инвариант проверяется тестом на 20k значений |
| Влияние на CI | Гейт только на floor-NFR (100k знач/мин на ядро, п. 18): замер одной горутиной, порог ниже факта ~×1000 — ложных падений на медленных раннерах не ожидается; верхней границы нет (отчёт — про наблюдаемость, не про регресс-гейт) |

## Принятые риски / ограничения

- **Абсолютный порог NFR зависит от машины** — осознанно: п. 16.8
  требует именно проверку NFR на PR; запас порядка трёх порядков
  (факт ~101M знач/мин на ядро против 100k) делает гейт устойчивым.
- **Микс 25/75 — соглашение, не измерение**: реальные БД имеют иной
  профиль; bench измеряет скорость recognizer'ов, а не представительность
  микса. Изменение — флагом `-pos`.
- **Кросс-матчи recognizer'ов** (ИНН-10 ↔ паспорт, phone ↔ паспорт/
  СНИЛС) не скрываются и считаются нормой профиля — прецедент:
  security-note этапа 6б.
