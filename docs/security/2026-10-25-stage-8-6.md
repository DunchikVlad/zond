# Security note: CSRF-фикс формы запуска и евиденс вердиктов (S8-6)

Дата: 2026-10-25
Изменение: middleware CSRF принимает токен hidden-полем `csrf_token`;
evidence вердикта пополнен маскированными примерами сэмпла и объяснениями
LLM/верификатора.

## CSRF: ослабление или нет?

Поля формы — равнозначная double-submit пара cookie+значение:

- токен по-прежнему 256 бит энтропии, непредсказуем для cross-site;
- cookie `SameSite=Lax` — cross-site POST cookie не несёт, значит чужой
  сайт не знает tok и не может его подставить ни в заголовок, ни в поле;
- требование «значение == cookie» сохранено (расхождение → 403, тесты);
- классическая форма (не JS) исторически стандартно защищается именно
  hidden-полем — прежний вариант (только заголовок) фактически блокировал
  не-JS мутации, что и было багом эксплуатации, а не усилением.

## Evidence: что теперь хранится и почему это безопасно

| Поле | Содержимое | Основание |
|---|---|---|
| sample.examples | до 3 значений сэмпла, пропущенных через mask.Mask (профиль п. 10.2) | ADR-0010: только маскированные примеры; значения < mask.MinLen исключаются (риск реидентации) — по той же причине, по которой они не отправляются в LLM |
| llm.reason_ru / llm_verify.reason_ru | текст ответа модели (1..300 симв., валидация п. 5.3) | уже существовал в agent_calls; теперь дублируется в вердикт для UI/ревью; LLM отвечает по маскированным значениям, сырых данных в причине нет |
| llm.agent / llm.model | идентичность агента | уже учитывалась в agent_calls (п. 10.6) |

Хранилище — тот же столбец evidence вердиктов (доступ по RBAC п. 11.3:
viewer/admin). Экспорт вердиктов по-прежнему отдаёт только маскированное.

## Принятые риски

- **Объём evidence** вырос (примеры + причины). Ограничения: ≤3 примера ×
  ≤200 символов (mask.MaxStringChars), reason ≤300 — рост строки вердикта
  ограничен единицами КБ в худшем случае.
- **Cache-hit не сохраняет reason** — кэш хранит label/conf/prompt_version;
  в UI это явно помечено («объяснение кэшем не сохраняется»).
