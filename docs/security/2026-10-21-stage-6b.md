# Security note: eval-harness (инкремент 6б, п. 16.6)

Дата: 2026-10-21
Изменение: пакет `internal/evalharness`, подкоманда `cmd/eval run`,
артефакт `evals/reports/report.json`, `evalset.Read`, цель `make eval`.

## Поверхность изменения

- Новый код: `internal/evalharness` (каскад-драйвер, метрики, отчёт),
  `evalset.Read`, LLM-wiring в `cmd/eval run` (agent-proxy по реестру
  detectors.yaml).
- Новый артефакт в git: `evals/reports/report.json` — агрегаты прогона
  (метрики, sweep, экономика).

## Меры (blueprint п. 14; fail-closed — ADR-security-llm-isolation)

| Угроза | Мера |
|---|---|
| Утечка PII из датасета в отчёт | Отчёт — только агрегаты (счётчики, метрики, версии); значения колонок и их ID в JSON не попадают; spoof/embedded-поля не сериализуются |
| Отправка значений датасета во внешний LLM | Только с явным `-llm`; вызов идёт через `agentproxy` (единственная точка LLM, п. 10.1) с маскированием значений (п. 10.2), egress-политикой и allowlist (п. 10.7); по умолчанию (`make eval`) — слои 0+1, сети нет вообще |
| Чтение секретов | Ключ — только `api_key_env` выбранного агента (fail-fast при отсутствии); иных ENV/файлов секретов harness не читает; store/audit не затрагиваются |
| Несанкционированный endpoint (`-endpoint`) | Переопределение endpoint — явный флаг оператора; egress-проверка прокси выполняется всегда в конструкторе (loopback/RFC 1918 или allowlist; `proxy.offline: true` запрещает внешние) |
| Учёт `$` без прайс-листа store | Цены только из флагов `-price-in/-price-out`; нули → учёт токенов без стоимости (`prices_set: false` в отчёте) — никаких «угаданных» цен |
| Подмена baseline-отчёта | Отчёт детерминирован (без wall-clock): повторный прогон побайтово идентичен — любая правка видна в diff; регрессия recognizer'ов/таксономии проявляется как расхождение отчёта |
| Запись отчёта (`-out`) | `WriteReport` пишет один файл в заданный каталог (MkdirAll 0755, файл 0644), путей из данных нет |
| Логирование | CLI печатает агрегаты; значения колонок не логируются |

## Принятые риски / ограничения

- **Отчёт в git фиксирует качество классификатора** — внутренняя метрика,
  не секрет; сопоставление с будущими прогонами — штатное использование.
- **Кросс-матчи recognizer'ов** (ИНН-10 ↔ паспорт, спуф-имена ↔ слой 0)
  не скрываются: отчёт измеряет их явно (spoof-precision, per-label P/R/F1)
  — это сигнал для тюнинга словарей/порогов, а не уязвимость.
- LLM-режим против реального агента в сессии не прогонялся (нет стенда);
  изоляция тела запроса покрыта изоляционными тестами agentproxy (S4, п. 16 п. 3).
