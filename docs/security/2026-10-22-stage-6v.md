# Security note: метрики и наблюдаемость (инкремент 6в, п. 17)

Дата: 2026-10-22
Изменение: пакет `internal/observe` (Meter/Snapshot/Evaluator/Webhook),
миграция 0007 (alerts), `/debug/vars`, `/api/v1/stats/metrics`,
`/alerts`, webhook-доставка, depguard-исключение.

## Поверхность изменения

- Новый экспортируемый endpoint: `GET /debug/vars` (expvar-реестр),
  `GET /api/v1/stats/metrics`, `GET /alerts` (UI), таблица `alerts`.
- Исходящий HTTP: webhook алертинга (ENV `ZOND_ALERT_WEBHOOK`).
- Новая категория аудита: `alert` (raise/resolve, actor scheduler).

## Меры (blueprint п. 14; fail-closed)

| Угроза | Мера |
|---|---|
| Утечка внутреннего состояния через /debug/vars | Endpoint за аутентификацией API-mux и RBAC ActionView (как /cost); публикуемые данные — счётчики и агрегаты, без значений колонок/DSN/секретов |
| Утечка PII в метриках/алертах | Снимки и алерты содержат только агрегаты (числа, статусы, scan_id); message алертов собирается из метаданных (ADR-0010: сырых значений нет по построению) |
| SSRF через webhook | URL только из ENV (оператор инстанса), не из пользовательского ввода; клиент с таймаутом 5с, без ретраев; тело — фиксированная JSON-схема без данных источников |
| Подделка алертов (запись в alerts) | Пишет только evaluator процесса (store — единственный писатель, соединение single-writer); аудит raise/resolve идёт hash-chain (п. 14.2) — факт подъёма не подделать незаметно |
| Flood алертами (дубли каждые 5 мин) | Дедуп открытых по (rule,target) на уровне SQL (INSERT … WHERE NOT EXISTS в одном соединении); повторное срабатывание продлевает last_seen_at |
| Паника правила алертинга роняет фон | recover в scheduler-обёртке и в collect() evaluator'а; ошибки правил изолированы (лог), прогон не прерывается |
| net/http в новом пакете (обход изоляции LLM) | depguard обновлён осознанно: internal/observe — исходящий webhook алертинга, LLM не вызывает (изоляция п. 10.1 обеспечивается agentproxy, а не запретом net/http в других пакетах — прецедент api/auth/web) |

## Принятые риски / ограничения

- **Метрики доступны viewer'у** (операционная информация): агрегаты
  экономики (токены/$) и счётчики видны любому аутентифицированному
  просмотру — осознанно (как /cost); при необходимости сужения — отдельное
  решение по RBAC.
- **Правило backup_failed не реализовано** — бэкапа ещё нет (этап 7);
  закроется вместе с инкрементом backup (п. 15.2).
- **Webhook без подписи/секрета** — приёмник доверенный (URL из ENV
  оператора); HMAC-подпись — при интеграции с внешними SIEM (п. 14.2
  предусматривает SIEM-sink отдельно).
- **Оценка алертов каждые 5 мин** — задержка обнаружения до 5 минут
  (приемлемо для фоновых метрик; критичный audit_chain_break также виден
  на странице /audit при ручной верификации).
