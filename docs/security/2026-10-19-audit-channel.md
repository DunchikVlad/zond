# Security note: аудит-канал (инкремент 5а, ADR-0013)

Дата: 2026-10-19
Изменение: `audit_log` + hash-chain + события движка + `zond audit verify|export`

## Поверхность изменения

- **Новая таблица `audit_log`** (миграция 0004): append-only (триггеры
  UPDATE/DELETE → ABORT), цепочка хэшей `entry_hash = sha256(prev_hash |
  canonical(seq,ts,actor,category,action,target,details_json))`, genesis
  prev_hash = "". Индексы по ts/actor.
- **Новые события**: scan_start/scan_finish (actor `cli`), agent_call на
  каждый вызов LLM (1:1 с agent_calls, ссылки call_id/scan_id/verdict_id,
  экономика). Категории auth/authz/review/config/secrets/admin
  резервированы под SSO/API (инкремент 5б+).
- **CLI**: `zond audit verify` (пересчёт цепочки), `zond audit export`
  (JSON, фильтры; сам экспорт аудируется до выдачи).

## Меры (blueprint п. 14.2)

| Угроза | Мера |
|---|---|
| Подмена/удаление записей | hash-chain + программная верификация (`audit verify`); runbook `audit-hash-chain-broken.md` |
| UPDATE/DELETE из кода/консоли | триггеры миграции 0004 (защита в глубину) |
| «Действие без аудита» | аудит в той же транзакции, что вердикты/вызовы (SaveVerdictsWithCalls); scan_start без аудита отменяет скан; export без аудита не выдаёт данные |
| Утечка значений через аудит | details без сырых значений (ADR-0010): только идентификаторы, статистика, экономика; секреты — никогда |

## Принятые риски / ограничения

- Внешний sink (SIEM/WORM) и подписанные снапшоты — не в инкременте: локальный
  журнал защищён цепочкой, но единственная копия. До появления sink +
  backup-процедуры (п. 15.2) восстановление при компрометации файла БД
  невозможно — для prod-контура это блокер, отслеживается в DoD п. 22.
- Actor = `cli` до появления SSO; подмена автора в CLI-контуре = доступ к
  хосту (вне модели угроз приложения).
- Retention (≥180 дней) не enforced — ждёт scheduler (п. 15.4).
- Проверка цепочки — полный пересчёт; инкрементальная верификация от
  последнего доверенного seq появится со снапшотами.

## Чек-лист privacy-review (п. 18.2)

- Что получает: только данные событий (идентификаторы, статистика).
- Где хранит: `audit_log` в SQLite инстанса (тот же файл, что Verdict Store).
- Как логируется: сам себя не дублирует; событие экспорта — одно.
- Чем ограничен egress: никаких внешних вызовов; sink — позже, за опцией.
