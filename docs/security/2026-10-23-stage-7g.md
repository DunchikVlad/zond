# Security note: релиз v0.1 — security-гейт и пробелы п. 14 (инкремент 7г)

Дата: 2026-10-23
Изменение: бампы зависимостей (goxmldsig, go-jose, toolchain go1.27.3),
`auth.AttemptLimiter`, idle-timeout сессий, `logging.SecretRedactor` + wire
в scan/serve, CSRF double-submit в web, Makefile release/CI-гейты
(govulncheck, go-licenses), release.yml, smoke-контур.

## Поверхность изменения

- Аутентификация API: новый отказ 429 `rate_limited` (код конверта ошибок).
- Логирование: обязательное маскирование message и строковых атрибутов
  (до этого — NoopRedactor с этапа 0).
- Web-UI: все HTMX-мутации теперь требуют пару cookie+заголовок CSRF.
- Сессии: скользящий idle-timeout (default 12 ч).
- CI: два новых блокирующих гейта; релизный pipeline с OIDC-подписью.

## Меры (п. 14; fail-closed)

| Угроза | Мера | Комментарий |
|---|---|---|
| Brute-force admin-токена | Лимитер: 5 неудач/10 мин с IP → блок 15 мин; блок проверяется до verify креденшелов | In-memory, подходит для single-instance (п. 15.1); за reverse-proxy — ограничение на hop'е (п. 15) |
| Секреты в логах | SecretRedactor: DSN-учётки, Authorization/Bearer/Basic, X-Admin-Token + явные env-значения (по конфигу и эвристике имён) | П. 14.1 «редко ловушки» — авто-тест зелёный; эвристика имён может маскировать лишнее — приемлемо |
| CSRF | Double-submit cookie+заголовок на мутациях, 403 при расхождении; SameSite=Lax второй слой | Cookie не HttpOnly намеренно (HTMX читает через JS); значение — 32 байта rand, не предсказуемо |
| Угон сессии (простой) | Idle-timeout 12 ч скользящий | Абсолютный TTL 12 ч сохранён; рестарт разлогинивает (п. 11.3) |
| Уязвимости зависимостей | govulncheck в CI блокирует; 3 находки закрыты бампом, не подавлением | goxmldsig — подпись SAML (критично для SP); toolchain go1.27.3 |
| Лицензии зависимостей | go-licenses check (бан GPL/Commons Clause) в CI | Игноры: собственный модуль (нет LICENSE-файла — вопрос владельцу), segmentio/asm (MIT на корне) |

## Принятые риски / ограничения

- **429 для легитимного клиента за NAT**: счётчик по IP — при массовых
  неудачах одного NAT'а могут страдать соседи; компенсация — аудит
  `auth_rate_limited` и ручной `Reset` рестартом. Внешняя конфигурация
  параметров — отдельным инкрементом.
- **Redactor не видит секреты, не из env** (например, kv-v2 значение,
  прочитанное только из Vault): паттерны DSN/заголовков покрывают типовые
  утечки; явные Vault-значения в redactor не передаются намеренно (не
  хранить их ещё и в логгер-компоненте).
- **CSRF-cookie и XSS**: защита от чтения cookie — CSP 'self' + экранирование
  html/template (п. 14); без XSS double-submit непроходим для атакующего.
- **Новый код ошибок `rate_limited`** — совместимое добавление п. 18.1
  (клиенты могут игнорировать неизвестные коды).
