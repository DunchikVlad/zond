# Безопасность: S9-3 — пользовательский промпт на скан

Дата: 2026-10-26
Код: коммит S9-3 этой даты.

## Контур доверия

- Инструкция принимается только по аутентифицированным каналам с действием
  `scan` (SSO admin / API-токен со scope `scan`): REST — `requireAction`,
  web — POST под CSRF и сессией, CLI — локальный оператор. Viewer инструкцию
  передать не может.
- Конверт вызова (п. 5.3) не изменился: `column_native_type`, маскированные
  `values`, `taxonomy_version`. Идентификаторы инфраструктуры в LLM не
  попадают ни с инструкцией, ни без — авто-тест изоляции п. 16.3 расширен
  (вызывов с инструкцией проверяются на отсутствие сырых значений).
- Инструкция не может подменить enum лейблов, схему ответа и
  анти-инъекционные правила: блок `<operator_instruction>` идёт после них и
  текстуально фиксирует их неотменяемость; ответ по-прежнему валидируется
  строго (label из таксономии, confidence [0,1], sensitivity enum,
  reason_ru [1,300]).
- Scheduled-прогоны не принимают пользовательский ввод: всегда стандартный
  промпт и default-LLM (тест фиксирует пустой UserPrompt и отсутствие
  LLM-override).

## Fail-closed на границе

- Нормализация `prompts.NormalizeUser` на каждом входе (REST/web/CLI/runner):
  trim, ≤2000 символов, NUL запрещён. Невалидный ввод — 400 до runner.
- REST: лимит тела 1 МБ (`MaxBytesReader`), строгий разбор JSON
  (`DisallowUnknownFields`) — опечатки полей и подмена конверта не проходят.
- Resume не принимает новый промпт: `-prompt` с `-resume` отклоняется в CLI,
  REST/UI resume воспроизводят сохранённый текст; сверка `prompt_base_version`
  и `prompt_hash` fail-closed (пустые legacy-значения несовместимы).

## Аудит и хранение

- `scan_start` фиксирует actor (SSO-субъект/токен/cli/scheduler), prompt_hash,
  длину и llm-флаг — без полного текста (ADR-0013; hash-chain не затронут).
- Полный текст — только в `scans.prompt_text` (тот же контур защиты, что и
  вердикты: шифрование тома БД по требованиям инсталляции). Хэш входит в
  ключ кэша: чужая инструкция не получит чужие закэшированные ответы.
- Хранение prompt_text оправдано воспроизводимостью resume; при retention
  удаляется вместе со сканом.

## Вывод

Новый канал ввода закрыт RBAC, лимитами и строгим разбором; изоляция данных
(ADR-security-llm-isolation) не ослаблена — дополнение зафиксировано в ADR.
