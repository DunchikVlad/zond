# Безопасность: S9-1

Дата: 2026-10-26
Код: `691d0f4`.

## Закрытые риски

- **Stored/reflected XSS в HTMX**: ручной фрагмент `/sources/test` больше не
  вставляет имя или ошибку как разметку; обе строки проходят `html.EscapeString`.
- **Утечка секрета в connections.yaml**: regexp привязан ко всей строке пароля;
  смешанный plaintext, несколько ENV-ссылок и malformed syntax запрещены.
  DSN/URI в audit details не записываются.
- **Невалидный итоговый конфиг**: помимо записи источника проверяются глобальные
  инварианты Connections, включая Vault, дубли, SSO/backup/audit и лимиты.
- **Потерянные параллельные правки**: один mutex сериализует файл, runtime и
  аудит; уникальные temp-файлы устраняют совместное использование `.tmp`.
- **Неаудированное изменение**: ошибка hash-chain отменяет успешное изменение;
  старый файл и runtime восстанавливаются. Ошибки компенсации возвращаются
  вызывающему через `errors.Join`, не маскируются.
- **Файл/runtime расходятся**: apply failure откатывает файл; production callback
  до atomic swap возвращает ошибку без частичного применения.
- **Коллизия данных разных схем**: qualified identity исключает overwrite
  вердиктов и чекпоинтов одноимённых таблиц. Экранирование разделителей закрывает
  неоднозначность имён с точками; length-prefix закрывает склейку полей ID.
- **Resume под другой конфигурацией**: provenance сравнивается fail-closed,
  отсутствующие legacy-поля не считаются совпадением. REST/UI требуют ActionScan,
  классические формы защищены CSRF, actor продолженного прогона сохраняется в
  `scan_start.resume_from`.

## Provenance и секреты

`config_fingerprint` — только SHA-256 эффективного снимка. Пароль из URL userinfo
удаляется до хеширования; Vault хранит лишь ref. Проверка детерминизма и
инвариантности при ротации пароля покрыта тестом. Изменение detectors меняет
fingerprint даже при неизменном текстовом `detectors_version`.

## Остаточные ограничения

- Mutex сериализует запросы одного процесса; одновременная внешняя правка файла
  или несколько пишущих инстансов по-прежнему вне поддерживаемой single-instance
  модели. Ошибка восстановления явно сообщается оператору.
- Старые строки не получают guessed schema/provenance. Это намеренный fail-closed:
  их resume отклоняется; исторические данные и audit chain не переписываются.
- Поле binary version в dev-сборке без ldflags равно `dev`; различие таких сборок
  ограничено метаданными, переданными при сборке. Релизный Makefile заполняет его.
