# Security note: веб-UI (инкремент 5г, п. 11.3)

Дата: 2026-10-20
Изменение: server-rendered UI (internal/web) + scheduler.

## Поверхность изменения

- Новые пути (за тем же SSO-cookie): страницы /scans, /scans/{id},
  /verdicts, /review (+POST-действия), /drift, /cost, /audit (admin),
  /settings; статика /static/* (embed: htmx.min.js, style.css).
- POST-действия UI: старт/стоп сканов, ревью (confirm/reject/relabel,
  bulk) — RBAC viewer запрещён (п. 11.3), actor — субъект сессии.
- Scheduler (фон): TTL-прочистка кэша, retention сканов 90 дней,
  пересканы по расписанию источников (actor "scheduler").

## Меры (blueprint п. 14)

| Угроза | Мера |
|---|---|
| XSS через LLM-ответы (reason_ru) и данные БД в UI | html/template с контекстным экранированием везде; safeHTML не используется; CSP `default-src 'self'` (без inline script/style); nosniff, no-referrer |
| Утечка секретов в /settings | DSN/URI источников не рендерятся (в Bundle они с интерполированными секретами — вывод только name/type) |
| Утечка сырых значений через evidence | рендер whitelist-ключей (rules/sample/llm_cache/reason/budget/cluster); тест: посторонняя строка в evidence не попадает в HTML |
| Неавторизованные действия UI | тот же SessionStore/RBAC, что API; POST без сессии → 403, GET → 302 /saml/login; /audit admin-only (п. 11.3) |
| CSRF | cookie SameSite=Lax (п. 14); HTMX POST без дополнительного CSRF-токена — риск ниже при Lax, но формальный п. 14 (CSRF-токены во всех HTMX-мутациях) закрыт частично — см. ограничения |
| SSRF/egress из UI/scheduler | UI не ходит наружу; scheduler дёргает только локальный runner |

## Принятые риски / ограничения

- **CSRF-токены в HTMX-мутациях не внедрены** — полагаемся на SameSite=Lax
  (п. 14 требует явные токены). Зафиксировано как доработка: double-submit
  cookie + hx-headers на странице ревью; приоритет — после TLS-контура
  (SameSite=None в prod требует токены обязательно).
- HTMX vendored (1.9.12) — фиксированная версия; обновления — ручным
  бампом файла с проверкой SBOM/лицензии (MIT).
- Retention audit_log — не автоматизирован (append-only); архив вне скоупа
  инкремента (runbook, этап 7 SIEM/WORM).

## Чек-лист privacy-review (п. 18.2)

- Что получает: вердикты (маскированные evidence), метаданные сканов,
  аудит-события (без значений).
- Где хранит: ничего нового (тот же SQLite); статика — embed в бинарнике.
- Как логируется: access-log web — не внедрён (есть API access-log); действия
  — в аудите через ApplyReview/scheduler.
- Чем ограничен egress: никаких внешних вызовов.
