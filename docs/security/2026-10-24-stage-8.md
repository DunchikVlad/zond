# Security note: resource governance (инкремент 8-1, п. 13.2)

Дата: 2026-10-24
Изменение: классификация причин ошибок источников, retry на retryable,
circuit breaker per source, `scan -resume`, миграция 0008
(`scan_tables.reason`).

## Поверхность изменения

- Новый код: `internal/connector/errors.go` (+ классификаторы в подпакетах
  clickhouse/mongodb), `internal/scanengine/breaker.go`, правки
  `scanengine/engine.go`, `verdict/store` (reason/DoneTables/
  LastCheckpointScan), CLI `-resume`, serve-интеграция breaker'а.
- Новая миграция 0008 — добавляющая (конвенция), колонка `reason`
  DEFAULT ''.
- Внешние эффекты: повторные сканы источника в паузе отклоняются; скан
  прерывается после 5 подряд overload-таблиц.

## Меры и свойства (blueprint п. 14, fail-closed)

| Вопрос | Ответ |
|---|---|
| Может ли breaker заблокировать источник навсегда? | Нет: пауза фиксирована (5 мин, константа спецификации); `PausedErr` чистит истёкшую паузу; повторный Trip в паузе продлевает, не бесконечно (until = now+5 мин) |
| Можно ли навязать паузу чужому источнику? | Нет: breaker — локальное состояние процесса, трипает только прогон от этого инстанса; атакующий без права на скан источника не трипает его (Start API требует auth, CLI — локальный) |
| Утечка секретов через reason/error | Reason — enum-строка из фиксированного множества; текст ошибки драйвера уже писался в `scan_tables.error` (прецедент); в аудит `source_paused` уходят только source/счётчики/until — без DSN и текста ошибки |
| Аудит | Трип паузы — событие `source_paused` от actor прогона (п. 14.2); отказанный в паузе прогон строку scans и аудит не создаёт (действие не совершено) |
| Retry и нагрузка на источник | Только retryable (перегрузка/лидерство), ≤3 попыток, backoff 250мс/1с — суммарно ≤ ~1.3 с на таблицу; ошибки store не ретраятся (не бьют по БД-источнику) |
| Отмена vs перегрузка | `context.Canceled` явно не overload — мягкая остановка (п. 11.2) не считается болезнью источника и не трипает breaker |

## Принятые риски / ограничения

- **Состояние паузы теряется при перезапуске процесса** — осознанно:
  пауза 5 мин защищает источник от сканера; защита от «забыть и долбить»
  после рестарта — операторская (алертинг llm_unavailable-стиля для
  серии failed — отдельная история, п. 17).
- **Классификация эвристична** (коды драйверов): неизвестная ошибка
  трактуется консервативно как не-overload (fail-safe: без retry и без
  счёта breaker'а — лучше частный partial, чем ложная пятиминутная
  блокировка источника).
- **Resume перечитывает failed-таблицы целиком** — чекпоинт только
  по таблицам, не по колонкам (прецедент п. 13).
