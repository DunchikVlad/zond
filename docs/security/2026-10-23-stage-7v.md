# Security note: Vault — резолвер секретов (инкремент 7в, ADR-0012, п. 12.1)

Дата: 2026-10-23
Изменение: пакет `internal/secrets` (+ `hashicorp/vault/api` v1.16.0 —
новая прямая зависимость), блок `vault:` в `connections.yaml`,
`Source.Ref`, проводка в `cmd/zond` (scan/serve) и `internal/doctor`,
аудит-категория `secrets` (константа уже существовала).

## Поверхность изменения

- Исходящие обращения к Vault: чтение секретов (коннект, doctor
  online), renew лиз (фоновая горутина), kubernetes login.
- Конфигурация: адрес Vault, auth (method/token_env/role/jwt_file),
  пути secrets — без секретных значений.
- Демо-контур: `deploy/docker-compose.vault.yml` (dev Vault, loopback).
- Аудит: события resolve/lease_renew/lease_revoked/renew_failed.

## Меры (blueprint п. 14; fail-closed)

| Угроза | Мера |
|---|---|
| Утечка секрета в логи/аудит/отчёт | Значения живут только в памяти на срок лизы; аудит и doctor-отчёт содержат только ref+path; хук аудита получает ref/path/action, значение недоступно; токен в конфиге невозможен (строгая схема ADR-0009) |
| Компрометация токена Vault | token — только env (dev) или JWT сервис-аккаунта + kubernetes login (prod); env-имя в конфиге, значение — нет; секрет не материализуется на диске |
| Подстановка чужого Vault (MITM/фейк) | Адрес из конфигурации оператора; prod-контур обязан использовать https (п. 15, TLS-сертификаты); dev compose — loopback-only; для k8s JWT подписан сервис-аккаунтом, Vault валидирует подпись |
| SSRF через Vault-пути | Пути — из конфига оператора, не извне; resolver не принимает путь извне (только ref → запись конфигурации) |
| Зависание на недоступном Vault | Таймаут 10 с на вызов; `SetMaxRetries(0)` — без библиотечных ретраев; источник → failed с `vault_unavailable`, остальные источники сканируются (R11); валидная лиза из кэша — до истечения |
| Продление чужой/отозванной лизы | renew идёт по lease_id из собственного кэша; 403 → кэш сброшен немедленно, событие `lease_revoked` в аудит; иначе кэш живёт только до expiresAt (fail-safe) |
| Утечка через renewer после shutdown | `Close()` останавливает горутины (wg.Wait) и отменяет контекст; serve/doctor закрывают resolver; doctor дополнительно закрывает по завершении прогона |
| Перебор секретов через doctor | doctor читает только записи из конфигурации инстанса; аудит doctor-чтений отключён (hook=nil), чтобы не мусорить в hash-chain |
| Граница «вызов LLM только через agentproxy» (depguard) | `internal/secrets` не импортирует `net/http`; Vault — не LLM-эндпоинт, изоляция агента не нарушается |

## Принятые риски / ограничения

- **kv-v2 не кэшируется** (D2): каждый коннект читает Vault — доступность
  Vault становится критичной для старта коннекта; компенсация — R11
  (кэш лиз) применим к dynamic, повторные прогоны по расписанию.
- **Реконнект внутри длительного скана** при отзыве лизы — на следующем
  коннекте, не мгновенно (коннектор открывается на скан; D3).
- **Dev-контур Vault** (compose) — dev-режим (root token из env, без
  TLS/seal): только loopback и только для проверок; runbook это
  фиксирует.
- **Флаки `make test -race` под нагрузкой** (`internal/audit`, не
  затронут инкрементом) — зафиксирован в progress, в изоляции стабильно.
