# Безопасность: S9-2 — per-column LLM evidence

Дата: 2026-10-26
Код: коммит S9-2 этой даты.

## Изоляция данных (ADR-0010, ADR-security-llm-isolation)

- В новые колонки `agent_calls` (answer_*, reason_ru, error) и в расширенный
  evidence попадают только ответы агента и служебная экономика — никаких сырых
  значений колонок; сэмплы в evidence по-прежнему только маскированные.
- Текст ошибки вызова обрезается до 300 символов: стектрейсы в журнале не нужны,
  а длинные строки в SQLite нежелательны. Endpoint/DSN в ошибках не фигурируют
  (proxy возвращает обобщённые ошибки).
- `error` верификатора и классификатора — внутренние причины отказа, не
  пользовательские данные.
- Ключ кэша не изменился; в записи кэша теперь хранится объяснение reason_ru —
  это ответ модели на маскированные значения, не сырые данные.

## Fail-closed и аудит

- Фильтр `llm_status` в API валидируется по белому списку: неизвестный статус →
  400 `invalid_request`, в store уходит только допустимое значение.
- Web-обработчик мягко игнорирует неизвестный статус (fail-closed к «без
  фильтра» не применим — UI-фильтр не несёт риска; сторона API строгая).
- Каждая новая запись вызова идёт с парным аудит-событием `agent_call` в той же
  транзакции, что и вердикт (ADR-0013: действие без аудита не совершено);
  hash-chain не ломается (существующий тест AuditVerify/цепочки проходит).
- Новые endpoint'ы (`/api/v1/verdicts/{id}/agent-calls`, `/verdicts/{id}/calls`)
  — только чтение, под ActionView (viewer); запись ошибок аудита не добавляет.

## Вывод

Расширение evidence не меняет контур изоляции: новые поля — ответы LLM и
метаданные вызова, контроль доступа и аудит сохранены, маскирование сырых
значений не затронуто.
