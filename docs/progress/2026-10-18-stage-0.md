# Прогресс по задаче: этап 0 — скелет проекта и контракты

Дата: 2026-10-18  
Исполнитель: Coordinator / Stage 0  
Статус: planned

## 1. Цель
Подготовить минимальный, но рабочий скелет проекта `classifier`, достаточный для начала реализации по blueprint:
- каркас Go-репозитория,
- базовую структуру пакетов,
- контракты ядра,
- конфигурацию,
- базовые команды сборки и проверки,
- основу CI/качества,
- стартовую документацию.

## 3. Объём работ
Что входит в этап:
- создание структуры директорий проекта;
- инициализация Go-модуля;
- добавление `cmd/classifier`;
- заготовка `internal/config`;
- заготовка `internal/connector/contract.go`;
- заготовка `internal/verdict/model.go`;
- базовый `Makefile`;
- стартовые конфиги в `configs/`;
- стартовые docs и правила документирования;
- первичная настройка lint/test workflow.

Что не входит:
- полноценный ClickHouse connector;
- полноценный MongoDB connector;
- реализация Agent Proxy;
- REST API / web UI;
- SQLite store;
- SSO, audit, Vault;
- production-ready scan engine.

## 4. Что сделано
План работ этапа:
1. Создать каркас репозитория и базовые директории.
2. Описать минимальные доменные контракты.
3. Добавить базовую загрузку и валидацию конфигов.
4. Добавить точку входа CLI с подкомандой `version`.
5. Подготовить `Makefile` для `build`, `test`, `lint`.
6. Добавить стартовые documentation artifacts.
7. Зафиксировать ограничения этапа и критерии продолжения.

## 6. Ключевые решения
Предварительно зафиксированы следующие решения:
- начинать с вертикального скелета, а не с “полной инфраструктуры”;
- не раздувать контракты сверх blueprint;
- держать интерфейсы на стороне потребителя;
- сразу вести документацию по шагам;
- проверять архитектурные границы с самого начала.

## 7. Допущения и ограничения
Допущения:
- этап 0 не обязан содержать бизнес-функциональность сканирования;
- допустимы минимальные заглушки, если они честно помечены как scaffold;
- документация этапа должна быть полноценной уже сейчас.

Ограничения:
- без скрытых временных решений;
- без несогласованных внешних зависимостей;
- без нарушения package boundaries;
- без ложных заявлений о готовности к production.

## 8. Проверки
Запланированные проверки:
- `go test ./...`
- `go vet ./...`
- `golangci-lint run`
- сборка `classifier version`
- базовая проверка чтения конфигов

## 9. Риски / что важно учесть
- риск раздутия каркаса раньше времени;
- риск внести неправильные доменные контракты до начала вертикального среза;
- риск забыть зафиксировать provenance/compatibility decisions;
- риск недодокументировать стартовые допущения.

## 10. Следующие шаги
- реализовать каркас модулей;
- подготовить минимально компилируемый CLI;
- оформить первую validation note;
- запустить первичные проверки;
- при успехе перейти к этапу 1 (вертикальный срез ClickHouse → rules → verdict).
