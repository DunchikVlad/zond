# Прогресс: этап 8, инкремент 8-7 — управление источниками и расписаниями из UI

Дата: 2026-10-25
Исполнитель: агент сессии
Статус: **done** (S8-7, код `8e63797` + фикс `2a38eda`; ПРОВЕРЕНО НА СТЕНДЕ).
Отвечает на запрос эксплуатации: «в UI нет, как подключать базы на анализ
и задавать расписания пересканов».

## 1. Что сделано

| Чанк | Результат |
|---|---|
| S8-7 | Страница **/sources** (только admin, RBAC-действие `manage`): список источников, формы добавить/править/удалить; редактируются name/type/dsn/uri + **schedule (cron)** и **scan_window**; классические формы с csrf_token-полем (S8-6), удаление с hx-confirm |
| S8-7 | **config.SourceEditor** — правка connections.yaml через yaml.v3 Node: секционные комментарии и `${ENV}`-литералы сохраняются; валидация fail-fast (имя `a-z0-9_-`, тип, dsn/uri по типу, cron 5-полей, окно через полночь); **пароль в строке подключения — только `${ENV}`** (п. 12, fail-closed) |
| S8-7 | **Горячее применение без рестарта**: запись файла (атомарно, `.bak` перед заменой) → LoadConnections → atomic swap провайдера (web и engineRunner читают актуальные sources) → `scheduler.ReplaceSources` пересобирает cron-расписания и окна. Новый ENV применится после рестарта — с явным сообщением |
| S8-7 | Кнопка **«Проверить»**: `${ENV}` раскрываются (`config.ExpandEnv`), коннектор строится, Ping с 10-секундным дедлайном → результат фрагментом на странице |
| S8-7 | Аудит: `admin/source_add|update|delete` (actor — субъект запроса, секретов нет) |

## 2. Живой прогон на стенде (.113, сборка 2a38eda)

- GET /sources → 200; форма сохранения нового источника `ch-ui-test`
  (dsn с `${CH_TEST_PASSWORD}`, schedule `23 5 * * *`, окно `04:00-05:00`)
  → 303; в файле запись с сохранёнными `${ENV}`, `.bak` создан;
  в журнале службы без рестарта: «scheduler: периодический перескан
  настроен ch-ui-test» + «источники обновлены count=5».
- Открытый пароль в dsn → 303 с ошибкой, запись в файл **не** попала.
- Удаление → «источники обновлены count=4», запись исчезла.
- «Проверить» по ch-test → **OK** (реальный ping до ClickHouse стенда).
- Файл стенда после тестов в исходном составе (4 источника).

## 3. Ключевые решения

См. `docs/decisions/ADR-impl-stage-8-7-sources-ui.md`: файл остаётся
источником правды (ADR-0009), UI — редактор файла, а не БД-хранилище;
Node-правка вместо round-trip (секреты не попадают в сериализацию);
горячий reload ограничен sources (detectors/taxonomy — по-прежнему
рестарт, ADR-0014 в части детекторов не реализован).
