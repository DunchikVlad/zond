## 3. Ключевые решения и находки

- **Checksum vs форматные**: `HasChecksum=true` только у типов с самодостаточной
  контрольной суммой в одном значении (ИНН, Luhn, СНИЛС, IBAN) — по п. 5.6
  checksum → 0.99 (конец пайплайна). Счёт РФ без БИК — форматный
  (`HasChecksum=false`): ключ требует БИК, значение одной колонки недостаточно.
- **IP без regex**: строгий парсинг `netip`/`net.ParseIP` исключает ложные
  срабатывания regex-подхода (256.1.1.1 и т.п.); CIDR, host:port и IPv6-зоны
  отброшены явно (это не БД-значения, а сетевая нотация).
- **Дата — реальная проверка диапазонов**, а не только формат: 29.02 принимается
  только в високосный год, 31.04 отклоняется. Лейбл DATE_TIME (DATE_OF_BIRTH —
  по диапазону/контексту на кластерном слое, не regex).
- **Паспорт**: серия с ведущим 0 допустима (03xx/05xx реальны), отклоняется
  только нулевой номер — снята избыточная строгость первой итерации.
- **Вектора генераторами**: для checksum-типов ≥50/50 получены детерминированной
  генерацией по спецификации (ФНС/ЦБ/ISO) — исключена «ошибка в спецификации»
  ручного набора; негатив — испорченный контрольный разряд (линейные схемы).
- **Лейблы согласованы с taxonomy.yaml**: IBAN и счёт → BANK_ACCOUNT; UUID →
  IDENTIFIER; IP → IP_ADDRESS; дата → DATE_TIME (п. 5.5).
