## 2. Что подтверждено тестами

`internal/secrets/vault_test.go` (fake Vault на httptest):

- **TestResolveKV2 / TestResolveDynamicTemplate** — kv-v2 unwrap
  `data.data` и dynamic-шаблон с подстановкой username/password.
- **TestResolveDynamicCacheWhileLeaseValid** — до истечения лизы сеть
  не трогается (R11), после — прозрачный перезапрос (счётчики чтений).
- **TestResolveUnavailable** — стенд недоступен, кэша нет →
  `errors.Is(err, ErrUnavailable)` (оба режима: kv-v2 и dynamic).
- **TestRenewal** — фоновое продление ~в середине срока; аудит
  `lease_renew` без значений секрета.
- **TestRenewRevoked** — 403 на renew: кэш сброшен сразу, аудит
  `lease_revoked`, следующий Resolve читает новую лизу.
- **TestRenewTransientFailureKeepsCache** — 500 на renew: кэш жив до
  истечения.
- **TestAuditResolveHasNoValues, TestCloseIdempotent,
  TestAuthenticateToken/Kubernetes, TestNewFromConfig**.

`internal/config/config_test.go`: **TestConnectionsVaultValid** (оба
режима secrets + ref-источники) и **TestConnectionsVaultInvalid** —
11 negative-кейсов (ref без enabled; блок настроен при enabled=false;
нет address; token без token_env; неизвестный method; ref без записи;
запись без источника; key+template вместе; template без плейсхолдеров;
запись без режима). **TestConnectionsVaultTokenInConfigRejected** —
строгая схема отвергает `auth.token`.

`internal/doctor/doctor_test.go`: **TestRunVaultOnlineOK** (vault OK,
vault.read OK/FAIL по записям, ref-источник резолвится, ping stub'а
OK), **TestRunVaultAuthFail** (env без токена: vault FAIL, ref-источник
FAIL), **TestRunVaultOffline** (SKIP/SKIP). Прежние тесты без изменений
— обратная совместимость кодов отчёта.

## 3. Ограничения проверки

- Живой dev-контур `deploy/docker-compose.vault.yml` не поднимался:
  docker в окружении сессии отсутствует. Поведение резолвера покрыто
  httptest-стендом (тот же HTTP-контракт Vault: `/v1/<path>`,
  `/v1/sys/renew/<id>`); compose + runbook — для машины с docker.
- Kubernetes-аутентификация проверена fake-логином, не живым кластером.
- Реальные БД-стенды (192.168.31.119) в смоке не участвовали: dynamic
  database engine на них не настраивался (см. runbook, п. 3.2).

## 4. Вывод

Инкремент принят: резолвер Vault (kv-v2 + dynamic leases с продлением),
конфигурация с fail-fast валидацией, проводка через scan/serve/doctor,
аудит без значений и режим деградации R11 работают по спецификации
п. 12.1; doctor проверяет Vault реально (заглушка S7а снята).
