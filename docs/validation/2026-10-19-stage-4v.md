## 2. Что подтверждено тестами

- **agent_calls (п. 10.6, атомарность п. 13)** — E2E `TestAgentCallsRecorded`:
  на сценарий «две одинаковые колонки + кэш» ровно 4 записи
  (classify ok + cache_hit + 2 verify ok), все `verdict_id` существуют в
  `verdicts` (FK), идентичность agent/model и provenance (prompt_version,
  created_at) заполнены; у cache_hit токены/стоимость нулевые, у ok —
  по прайсу (1000/100 tok → $0.00021; итог со verify $0.00042).
- **Budget-стоп (п. 10.4)** — `TestBudgetExceededStopsLLM`: лимит $0.10,
  первый вызов стоит $0.15 → второй вызов не делается, вторая колонка
  pending с `evidence.budget_exceeded=true`, статус скана `budget_exceeded`,
  CostUSD=0.15. Отрицательный тест — `TestBudgetNotExceededBelowLimit`:
  лимит $1.0 → статус done, 4 записи вызовов.
- **Ошибки LLM** — `TestLLMErrorRecorded`: 500 у classify и verify на обеих
  колонках → 4 записи status=error (usage/cost 0), скан не падает,
  LLM-кандидат не подмешивается.
- **Per-table коммит** — `TestAgentCallsCommitPerTable`: failed-таблица
  (обрыв на GetSchema) не оставляет записей; буфер не протекает в коммит
  соседней таблицы.
- **Лимиты** — `TestGateLimitsPeakConcurrency` (пик ≤ 2 при Gate(2),
  6 параллельных вызовов), `TestGateRateLimit` (5 rps: 5 вызовов ≥ 0.8 с),
  `TestGateNoRateLimit`, `TestGateAcquireContextCancel` (слот не теряется),
  `TestGateDefaultMaxConcurrent` (0/−3 → 8).
- **Egress (п. 10.7)** — табличный `TestCheckEgress` (12 случаев:
  loopback/RFC 1918 разрешены; 203.0.113.10 запрещён; CIDR/IP/hostname-запись
  разрешает; offline запрещает loopback и чужую allowlist-запись),
  `TestCheckEgressBadURL` (fail-closed на мусорных URL),
  `TestNewValidatesEgress` (конструктор всегда проверяет).
- **Store** — round-trip `SaveVerdictsWithCalls`, FK (чужой verdict_id →
  ошибка), `PriceFor` (seed gpt-4o-mini/gpt-4o, неизвестная модель →
  ok=false), `TestMigrationsUpDownUp` покрывает 0003 автоматически.

## 3. Поведенческое изменение (зафиксировано осознанно)

`zond agent-check` в offline-режиме раньше сообщал OK по любому endpoint из
реестра, если env задан. Теперь прокси строится всегда → egress-политика
применяется всегда: демо-эндпоинты `api.example` дают FAIL (не резолвятся,
fail-closed). Это соответствует назначению agent-check как preflight
(п. 15.3) и дефолту п. 10.7; CI (`make config-check`) затронут не был.

## 4. Не проверено / ограничения

- Живой вызов LLM (`agent-check -online`, `scan -llm` против реального
  эндпоинта) не выполнялся — на стенде нет доступного агента; изоляция и
  протокол покрыты fake-LLM (httptest) и unit-тестами.
- Нагрузка Gate в боевом контуре (десятки конкурентных вызовов) — только
  синтетика тестов; при этапе 6 (eval-harness) появится реальная статистика.
- DNS-резолв в CheckEgress с таймаутом 5 с: при недоступном DNS старт
  прокси задержится до таймаута и будет отказ (fail-closed) — осознанный
  выбор, для публичных имён без DNS это «запрещено».

## 5. Остаточные риски

- Модели без записи в `model_prices` учитываются с cost 0 — budget-стоп по
  деньгам для них не работает (локальные контуры бесплатны; для внешних
  моделей прайс надо пополнять, иначе экономика п. 17 занижена).
- Verify после ошибки classify — осознанное решение (п. 3 ADR-impl-4в);
  при серии сбоев обоих агентов число вызовов удваивается — сдерживается
  budget-лимитом и rate-limit.
