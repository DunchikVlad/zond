# Валидация: smoke `zond scan -source ch-test` против живого стенда

Дата: 2026-10-18
Связанные документы:
- `docs/progress/2026-10-18-stage-1-vertical-slice.md` (следующие шаги №1–2)
- `docs/progress/2026-10-18-test-environment.md` (стенд 192.168.31.119)
- `docs/validation/2026-10-18-stage-1.md` (первичная валидация этапа 1)

Окружение: macOS (рабочая машина разработчика), Go 1.x, стенд `192.168.31.119`
в сегменте `192.168.31.0/24`.

## 1. Что валидировалось

Повторный прогон точки раннего сигнала blueprint п. 21: end-to-end
`zond scan -source ch-test` против реального ClickHouse на стенде, после
закрытия этапа 1 (коммит S1-8). Цель — получить первые вердикты на живой БД
либо зафиксировать точное текущее состояние стенда.

## 2. Проверки и результаты

| Проверка | Команда | Результат |
|---|---|---|
| Сборка + статика | `go build ./... && go vet ./...` | OK |
| Форматирование | `gofmt -l .` | чисто |
| Unit + E2E | `go test ./...` | все пакеты `ok` (meta, rules, config, connector, clickhouse, ensemble, logging, sampler, scanengine, store) |
| Конфиг, негатив | `zond config validate` (без env) | корректный отказ: перечислены незаданные `CH_PROD_PASSWORD, CH_TEST_PASSWORD, IDP_METADATA_URL, MONGO_PROD_URI, MONGO_TEST_PASSWORD`, exit 2 — секреты только через env (blueprint п. 12) |
| Стенд, сеть | `ping 192.168.31.119` | OK (icmp, 0% потерь, ~9 мс) |
| Стенд, SSH | `nc -z 192.168.31.119 22` | открыт |
| Стенд, ClickHouse | `nc -z -w 2 192.168.31.119 9000` | **нет ответа (таймаут)** — CH не поднят |
| Smoke E2E | `CH_TEST_PASSWORD=test CH_PROD_PASSWORD=test MONGO_TEST_PASSWORD=test MONGO_PROD_URI=mongodb://unused IDP_METADATA_URL=https://unused go run ./cmd/zond scan -source ch-test` | `list tables: dial tcp 192.168.31.119:9000: connect: no route to host`; отчёт: статус `failed`, таблиц 0, вердиктов 0, exit 1 |

## 3. Подтверждено поведение по blueprint

- **п. 6 (ошибки/отказы):** недоступность источника не роняет процесс с
  паникой — скан завершается управляемо, статус `failed`, печатается
  консольный отчёт с нулевыми счётчиками и понятной сетевой ошибкой.
- **п. 12 (секреты):** конфиг отказывает стартовать без env-переменных
  секретов; DSN стенда собирается из `configs/connections.yaml` с
  интерполяцией `${CH_TEST_PASSWORD}`.
- **п. 5.1 / п. 9 (коннектор CH):** точка отказа локализована на этапе
  `ListTables` — ожидаемо при закрытом порте 9000; до сэмплинга и слоёв 0–1
  выполнение не доходит (таблиц нет).

## 4. Что не проверено (с причинами)

- **Реальные вердикты на живом ClickHouse** — БД на стенде до сих пор не
  установлена (порт 9000 закрыт). Это блокирующее условие точки раннего
  сигнала blueprint п. 21.
- **MongoDB-источник `mongo-test`** — порт 27017 на стенде не проверялся
  (этап 2, отдельная задача).
- **Интеграционный тест ClickHouse (testcontainers) в CI** — зависит от
  наличия Docker на runner'е; на момент проверки не прогонялся.

## 5. Вывод и следующие шаги

Код этапа 1 собирается, линт/тесты/race — зелёные, CLI корректно отказывает
при недоступном источнике. **Точка раннего сигнала не пройдена не по причине
кода, а по причине отсутствия БД на стенде.**

Блокер снятия — инфраструктурный (см. `docs/progress/2026-10-18-test-environment.md`,
п. 7 «Открытые вопросы»):

1. Установить ClickHouse на `192.168.31.119` (SSH: `test@192.168.31.119`,
   пароль `test`; доступ подтверждён сегодня — порт 22 открыт).
2. Создать read-only учётку и синтетический датасет (blueprint п. 24, п. 16.6;
   реальные ПДн на стенде запрещены).
3. Повторить `zond scan -source ch-test` — ожидаются первые реальные вердикты
   (email/phone/ИНН/Luhn на синтетике).
4. После снятия блокера — переход к этапу 2: MongoDB-коннектор (flatten,
   полиморфизм, blueprint п. 8) + conftest против обеих БД (blueprint п. 16.2).
