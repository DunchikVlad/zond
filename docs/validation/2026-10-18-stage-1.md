## 3. Подтверждено поведение по blueprint

- п. 5.6: маппинги confidence (checksum 0.99; ≥0.9→0.90; 0.5–0.9→0.70; <0.5→0.50; словарь 0.85; regex 0.60) — тестами.
- п. 6: недоступная таблица → failed, скан продолжается, статус partial — тестом.
- п. 13: чекпоинт scan_tables после таблицы — в store и E2E.
- п. 16.1: золотые вектора стартовые (полные ≥50/50 и порт RU-набора — этап 3).
- п. 16.9: up → down → up на чистой БД + smoke query — тестом.
- ADR-0010: в evidence только статистика матчей, авто-тест отсутствия сырых значений.
- Детерминизм: равные confidence → стабильный результат (тест ensemble).

## 4. Что не проверено (с причинами)

- Реальный ClickHouse: на стенде 192.168.31.119 БД не установлены (порты 9000/8123
  закрыты, SSH 22 открыт) — после установки прогнать `zond scan -source ch-test`.
- Интеграционный тест CH в CI — первый прогон на GitHub Actions (Docker есть в runner'е).
- Stratification-статистика сэмпла (п. 5.1, п. 16.2) — с conftest на этапе 2;
  сейчас сэмпл случайный (ORDER BY rand() / $sample-эквивалент), но без
  стат-теста равномерности.
- Нагрузка: NFR ≥100k значений/мин (п. 18) — bench на этапе 3/6.

## 5. Остаточные риски

- Вектора ИНН/Luhn генерируются в тесте по спецификации — независимая сверка
  с эталонным набором (angryscan, Apache-2.0 + NOTICE) — этап 3, риск R7.
- ИНН 12: генератор и recognizer используют одни веса — против «ошибки в спецификации»
  защита только портом внешнего набора (этап 3).
