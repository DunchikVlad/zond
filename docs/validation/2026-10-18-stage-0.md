## 3. Покрыто тестами

- `internal/config`: строгая схема (неизвестный ключ отклонён), интерполяция
  post-parse (комментарий с `${VAR}` не мешает), список недостающих ENV, дубли
  источников/лейблов, dsn/uri — ровно одно, перевёрнутый confidence_band,
  escalate_to на несуществующего агента, tau_review ≥ tau_accept, sensitivity вне enum.
- `internal/connector`: регистрация/дубль/пустой тип/nil factory/lookup/сортировка Types.
- `internal/logging`: correlation id в JSON, фильтрация уровней, поле отсутствует без WithCorrelation.

## 4. Что подтверждено

- DoD этапа 0 (blueprint п. 21/22): рабочий `zond version`, валидируемый конфиг,
  CI-ворота (fmt, vet, build, test -race, lint) зелёные локально; workflow в `.github/workflows/ci.yml`.
- Fail-fast конфигурации соответствует п. 12/п. 18.1 blueprint (version-поля, список ошибок).

## 5. Что не проверено

- GitHub Actions: workflow запушен, первый прогон — на GitHub (ворота зеркалят локальные проверки).
- `deploy/docker-compose.yml`: отложено — Docker отсутствует в среде (см. gap analysis, п. 3.2).
- Depguard-правила слоёв проверены только «вхолостую» (инфра-импортов в domain пока нет);
  реальная проверка — когда появятся адаптеры (этап 1+).

## 6. Остаточные риски

- Контракты п. 5 не испытаны вертикальным срезом — возможны уточнения интерфейсов на этапе 1.
- Windows-окружение разработки отличается от CI (ubuntu): race требует mingw в PATH
  (в Makefile отдельная цель `test-race`, фиксация — в ADR-impl-zond-naming-and-scaffold).
