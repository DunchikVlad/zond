## 2. Что подтверждено тестами (`internal/evalharness/harness_test.go`)

- **Каскад и метрики с ручным расчётом** (TestRunRulesOnly): 6-колоночный
  датасет — EMAIL (meta+rules), TAX_ID (checksum 0.99 → rules auto),
  спуф ИНН-12 (meta по имени `inn_raw` → ложный TAX_ID), free_text со
  встроенным телефоном и mixed chaos (нет кандидатов → UNKNOWN pending),
  даты рождения (rules отдаёт DATE_TIME — recall DATE_OF_BIRTH = 0 без LLM,
  честно). Проверены tp/fp/fn, P/R/F1 per-label, micro (=0.5: TP=FP=FN=3),
  macro, by_kind (positive 2/3, spoof 0/1, free_text 0/1, mixed 1/1),
  spoof-precision=0, счётчики review_status.
- **Sweep** (TestSweep): F1_all инвариантен к tau без LLM (лейбл — лучший
  кандидат в любом случае), auto_accepted монотонно не растёт с tau
  (4 → 4 → 1 на сетке 0.50/0.80/0.95), F1_decided пересчитывается по
  подмножеству auto_accepted (0.5 → 1.0).
- **LLM-контур** (TestLLMCascade): серый коридор [0.5, 0.8] → classify
  (0.9) → пересборка (0.678 < tau) → verify confirm → auto_accepted,
  слой llm; учёт вызовов (2), токенов (150/30), $ (0.0006 при прайсе
  2/10 за 1M), per-1000 нормировка (150000/0.6), candidate, переданный
  верификатору.
- **Отказоустойчивость** (TestLLMErrorsAndSmallSample): ошибка classify не
  роняет колонку (pending, LLMErrors=1), пустая колонка — small_sample →
  UNKNOWN pending, LLM не вызывается.
- **Валидация конфига** (TestRunValidation): tau_accept вне (0,1] — ошибка
  до прогона.
- **Детерминизм и round-trip отчёта** (TestReportDeterministicAndRoundTrip):
  два BuildReport по одним данным сериализуются побайтово одинаково;
  WriteReport → JSON читается обратно с сохранением полей.
- **Сводка** (TestReportText): печатаются все ключевые блоки.
- **evalset.Read** (evalset_test.go): Write→Read без потерь; битый/пустой
  каталог — понятные ошибки.

## 3. Наблюдения прогона по датасету 1.0.0 (закоммиченный baseline)

- Чексумма-лейблы F1=1.000 (BANK_ACCOUNT, IDENTIFIER, IP_ADDRESS);
  EMAIL 0.966, PHONE 0.810.
- CARD_NUMBER spoof-precision=0.000 и SNILS=0.167: «имитирующие» имена
  колонок (`card_raw`, `pan_txt`, `snils_old`) триггерят слой 0
  (паттерны `card|pan`, `snils`) — harness измеряет эти ложные
  срабатывания явно (это свойство таксономии словарей, не дефект кода).
- ИНН-10-спуфы форматно совпадают с паспортом (10 цифр) — перекрёстные
  матчи rules видны в метриках; в тестах использован однозначный ИНН-12.
- Лейблы без recognizer'а (PERSON_NAME, ADDRESS, FREE_TEXT, …) имеют
  recall ≈ 0 без LLM — baseline для сравнения с LLM-режимом (S6б
  зафиксировал точку отсчёта).
