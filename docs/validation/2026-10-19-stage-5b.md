## 2. Live-smoke `zond serve` (без LLM, пустая БД)

Запуск: `zond serve -addr 127.0.0.1:18099` (env из configs/ci.env).

| Запрос | Результат |
|---|---|
| `GET /api/health` | 200 `{"status":"ok"}` |
| `GET /api/ready` | 200 `{"status":"ready"}` (Ping store) |
| `GET /api/v1/scans` | 200 `{"items":[],"total":0}` (не null-массив) |
| `POST /api/v1/scans {"source":"ghost"}` | 400 `invalid_request` в конверте (источник не найден) |
| `POST /api/v1/scans {"source":"ch-test"}` | 502 `source_unavailable` — стенд 192.168.31.119:9000 недоступен из этой сети (no route to host; тот же блокер, что S1-9). **Важно:** ошибка синхронная, до старта фонового прогона (ADR D4) |
| `GET /api/v1/verdicts` | 200 пустой список |
| `GET /api/v1/drift?source=ch-test` | 404/invalid_request «нужно ≥2 прогона» |
| `GET /api/v1/export?scan_id=ghost` | 404 `scan_not_found` в конверте |
| Заголовки | `X-Request-ID` генерируется и возвращается; входящий принимается; access-лог JSON с `correlation_id`, status, duration_ms |
| Shutdown | SIGTERM → graceful (лог «serve: остановка») |

## 3. Что подтверждено тестами

- **Store-чтения** (`review_api_test.go`): фильтры сканов status/source и
  пагинация с total (`TestListScansFiltersAndPagination`); ErrNoRows → 404
  (`TestGetScanNotFound`); фильтры вердиктов п. 11.2 и risk_first — PCI
  раньше PII, внутри класса confidence desc (`TestListVerdictsFiltered`);
  лимит экспорта: сверх max_rows → nil+total (`TestVerdictsForExportLimit`).
- **Ревью** (`TestApplyReviewHappyPath`, `TestApplyReviewConflicts`):
  relabel меняет status/final_label/reviewed_*, пишет review_events и аудит
  категории review, цепочка сходится; конфликты (повторный confirm, relabel
  на тот же лейбл, relabel без лейбла, неизвестное действие, ghost-вердикт)
  — ReviewConflict/ErrNoRows **без какой-либо записи** ни в review_events,
  ни в audit_log; триггеры append-only блокируют UPDATE/DELETE
  (`TestReviewEventsAppendOnlyTriggers`).
- **Экономика** (`TestScanCostStats`): агрегаты по (agent, model): calls
  без кэша, cache_hits, errors, токены, cost; итоги; no_llm_share = 0.5 при
  одном реальном вызове из двух вердиктов.
- **Дрейф** (`internal/verdict/drift`): added/removed/changed между
  прогонами; Δconf ≥ 0.05 — дрейф, < 0.05 — шум; final_label приоритетнее
  автоматического (ревьюерский relabel — дрейф); BetweenLatest берёт два
  последних не-running прогона именно этого источника, since отсекает
  старые.
- **API E2E** (`internal/api/server_test.go`, httptest + реальный store):
  все маршруты п. 11.2; конверт ошибок и коды; correlation id в ответе и
  принятие входящего; старт → 202 `{scan_id}`; stop → 202 + аудит scan_stop
  с actor `api`, повторный stop терминального — 409; ревью через API даёт
  журнал в карточке вердикта и аудит; экспорт JSON/CSV (Content-Disposition,
  заголовок CSV), аудит verdicts_export до выдачи; лимит → 409 +
  `details.async=true` и отказ НЕ аудируется как выдача; цепочка аудита
  сходится после смешанных операций (`TestAuditChainIntactAfterAPI`).
- **Движок** (`internal/scanengine/stop_test.go`): отмена ctx после первой
  таблицы → статус `interrupted` persisted, stats_json записан, аудит
  scan_finish в целой цепочке (`TestScanInterruptedByContextCancel`);
  ScanWithID использует заданный id (`TestScanWithIDUsesGivenID`).

## 4. Не проверено / ограничения

- **Реальный скан через API на живом источнике не выполнен** — тестовый
  стенд недоступен из сети разработчика (no route to host, блокер S1-9).
  Путь Start→горизонта→ScanWithID покрыт engine-тестом на fake-коннекторе и
  синхронной частью (валидация, Ping, регистрация) через live-smoke.
  Рекомендуется: на доступном контуре прогнать `POST /scans` против
  ch-test и проверить прогресс в `GET /scans/{id}`.
- `golangci-lint` локально не установлен — линт-ворота проверит CI; новый
  код держится в рамках правил (errcheck: все ошибки обработаны или
  осознанно `_ =` на нефейлящих записях в ResponseWriter).
- Rate-limit 100 req/s не реализован (нет субъектов до SSO) — ADR/progress
  «Не вошло»; сервер без аутентификации не выносить на внешний интерфейс
  (ADR D1).
- Конкурентные HTTP-запросы чтения во время прогона не нагружались стендом;
  store на SetMaxOpenConns(1) — запросы выстраиваются в очередь соединения
  (для MVP приемлемо; writer-очередь п. 15.1 — serve-этап scheduler).
- Async-экспорт сверх лимита — только намёк (409+details.async), самой
  фоновой выгрузки нет до scheduler.

## 5. Остаточные риски

- До инкремента 5в любой локальный пользователь с доступом к порту может
  стартовать/останавливать сканы и экспортировать вердикты — mitigated
  loopback-дефолтом; зафиксировано в security-заметке.
- `interrupted`-прогон, чей процесс убит до финализации (kill -9), останется
  running в store — лечится resume/janitor'ом этапа scheduler (п. 13);
  зафиксировано как известное ограничение.
- Дрейф-эндпоинт сравнивает только «два последних» прогона; произвольная
  пара (from/to) — развитие API при появлении UI-страницы /drift.
