# Валидация: CSRF-фикс запуска скана и евиденс вердиктов (S8-6) — 2026-10-25

Дата: 2026-10-25
Объект: фикс бага «CSRF-токен отсутствует или неверен» при запуске скана
из UI + детализация вердиктов (сэмпл, правила, объяснение LLM).
Код: `76b0d5a`.

## 1. Баг и фикс

Симптом: «Прогоны → Запустить скан» → 403 «CSRF-токен отсутствует или
неверен — обновите страницу». Причина: форма `/scans/start` — классический
HTML-POST, а CSRF-middleware (S7г-4) принимала токен только заголовком
`X-CSRF-Token` (htmx-запросы; кнопка «Стоп» — htmx, поэтому работала).
Форма заголовок не шлёт → гарантированный 403.

Фикс: middleware принимает double-submit пару и из hidden-поля
`csrf_token` (равнозначная семантика: токен непредсказуем, SameSite=Lax
сохранён); токен для рендера формы — из контекста (свежесгенерированный)
или cookie. Форма получила `<input type="hidden" name="csrf_token">`.

## 2. Статические ворота

| Проверка | Команда | Результат |
|---|---|---|
| Unit | `go test -count=1 ./internal/web/ ./internal/scanengine/` | ok |
| Race | `go test -race -count=1 ./internal/web/` | ok |
| Полный прогон | `make ci` | зелёный |

Тесты: CSRF form-field (форма с полем → 302, чужой токен → 403, без поля →
403); evidence движка (примеры замаскированы, ≤3, reason_ru LLM и
верификатора в evidence); evidenceLines (читаемый рендер правил/сэмпла/LLM).

## 3. Живой прогон на стенде (сборка 76b0d5a, systemd)

| Проверка | Результат |
|---|---|
| GET /scans | 200; в форме есть hidden csrf_token |
| POST /scans/start формой (cookie + поле, **без заголовка**) — ровно пользовательский сценарий | **302 → /scans/1792915911-efa0273c** (раньше 403) |
| Скан прошёл | прогон создан, вердикты записаны |
| /verdicts?scan_id=… — колонка «Евиденс» | раскрытия содержат: `сэмпл: значений 1, null 0 из 1 · примеры: "+7 495 777-**-99"` (маскированный пример) и `правила: rules/phone 1/1`; строк LLM/верификатора в прогоне без -llm нет — появятся при сканах с LLM (поля evidence.llm/llm_verify) |

## 4. Что увидит пользователь

- Вердикты прогона: раскрытие «сэмпл · правила · LLM» в каждой строке —
  маскированные примеры значений (до 3), сработавшие recognizer'ы с
  matched/total и пометкой checksum, объяснение модели и верификатора
  (reason_ru), пометки кластера/кэша/бюджета.
- Review-карточки рендерят те же строки.

ADR-0010 не нарушен: примеры идут только в маскированном виде (маск-профиль
п. 10.2), сырых значений в evidence по-прежнему нет.

## 5. Вывод

Запуск скана из UI восстановлен, евиденс вердиктов читаем. Ошибок
регресса нет. LLM-объяснения в евиденсе будут наполняться прогонами с
-llm (Kimi — после пополнения баланса, см. validation S8-5).
