## 2. Сценарии приёмки

### Cache hit/miss эквивалентность (движок)

- Два прогона с одинаковыми значениями и CacheScope: второй — статус
  `cache_hit`, `PromptVersion` вердикта заполнен (дефект hit-ветки закрыт),
  `evidence["llm"].reason_ru` идентичен первому прогону (кэш хранит объяснение).
- Miss: статус `called`, запись `operation=classify` с answer_label/confidence/
  sensitivity/reason_ru и экономикой; evidence содержит все новые ключи.
- Ошибка агента: статус `error`, запись `operation=classify, status=error` с
  непустым обрезанным `error`.
- Статусы пропусков: уверенный rules-вердикт → `not_called`; пустой сэмпл →
  `small_sample`; кластер → `cluster_propagated` (приоритет над small_sample);
  budget-стоп → `budget_exceeded`; существующие тесты budget/cluster расширены
  проверками статуса.

### Store и миграция 0011

- up/down/up без ошибок; открытие БД на схеме 0010 с существующими
  scan/verdict/agent_call — upgrade проходит, бэкфилл по фактам evidence.
- Round-trip новых полей AgentCall (SaveVerdictsWithCalls → ListAgentCalls/
  ListAgentCallsByVerdict); llm_status вердикта читается во всех путях выборки.
- Фильтр `VerdictFilter.LLMStatus` возвращает только нужные строки.

### API

- `?llm_status=cache_hit` возвращает только такие вердикты; неизвестный статус →
  400 `invalid_request` с details.
- `GET /api/v1/verdicts/{id}/agent-calls`: 200 `{items:[…]}` в хронологии,
  404 `verdict_not_found`; viewer (read-токен) допущен, аноним — 401.
- DTO вердикта содержит `llm_status`; цепочка аудита не нарушена
  (TestAuditChainIntactAfterAPI проходит).

### Web

- `/verdicts` содержит select llm_status и колонку «LLM»; фильтр применяется.
- Фрагмент `/verdicts/{id}/calls` возвращает вызовы; `<script>` в reason_ru/
  error присутствует только в escaped-виде; 404 для отсутствующего вердикта.
