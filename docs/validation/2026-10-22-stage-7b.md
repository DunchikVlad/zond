## 2. Что подтверждено тестами

- **store.Backup** (backup_test.go): round-trip копии — открывается как
  store, данные на месте (VerdictSummary), hash-chain сходится (учебное
  восстановление DoD п. 22); существующий файл не перезаписывается;
  права копии 0600 (POSIX); имя файла по времени.
- **LatestBackupEvents** — парсинг аудит-записей backup (status/path/
  error/ts, свежие первыми; пустой журнал — пусто).
- **Конфиг** — backup.schedule без dir отклоняется; корректная пара
  принимается.
- **Scheduler** (scheduler_test.go): задача backup по @every 1s создаёт
  файл в каталоге и пишет аудит ok; неудача в отсутствующем каталоге —
  аудит fail с ошибкой (источник сигнала для правила).
- **Правило backup_failed** (observe/alerts_test.go): 5 сценариев —
  неудача последней попытки → алерт; RPO нарушен (успеха >24ч) → алерт;
  расписание есть, попыток не было → алерт; свежая успешная копия →
  тишина; расписания нет и попыток не было → тишина. Авто-закрытие после
  успешной копии (open 1 → 0).
