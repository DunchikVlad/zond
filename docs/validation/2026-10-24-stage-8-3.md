## 2. Что подтверждено тестами

`internal/audit/sink_test.go` (in-memory «SIEM» на net.Pipe — без сети;
запись одного события синхронна, детерминированные assert'ы):

- **Порядок и без дублей**: два события → две NDJSON-строки, seq по
  возрастанию (1,2); повторный `Pump` — 0 доставлено, дублей на проводе нет
  (закладка за хвостом).
- **Потеря недопустима / повторная отправка**: sink недоступен (2 попытки
  падают) → закладка не двигается (`last_seq` остаётся 0), `last_error`
  фиксируется; после «восстановления» — доставка, закладка продвигается,
  `last_error` сброшен.
- **Догон между циклами**: событие, записанное после первого `Pump`,
  доставлено вторым (закладка догоняет журнал).
- **syslog/CEF**: полезная нагрузка — `CEF:0|DunchikVlad|zond|1|<seq>|audit|
  <seq>|msg=<canonical>` с канонической записью в `msg` (сверка hash-chain
  на стороне SIEM).
- **SinkPending**: backlog = события за закладкой (3 до доставки, 0 после).
- **Nil-safe**: nil-приёмник — `Enabled=false`, `Pump` no-op; nil db или
  пустой конфиг — nil sink (выключен).

`internal/config` (`window_test.go`, кейсы sink): 10 сценариев схемы
`audit.sink` (валидные json-tcp/syslog с proto по умолчанию/явным; отказы:
kind без address и наоборот, неизвестный kind, proto не udp|tcp, proto при
json-tcp, address не host:port).
