# Решение: формат миграций goose и упрощения вертикального среза (S1)

Статус: accepted
Дата: 2026-10-18
Автор: Coordinator / Stage 1

## 1. Контекст

На этапе 1 вводится Verdict Store с миграциями goose (ADR-0006, blueprint п. 11.1,
п. 16.9). При стандартной раскладке `0001_x.up.sql` + `0001_x.down.sql` goose
v3.24.2 и v3.29.0 падают паникой «duplicate version 1 detected» ещё при
коллекции файлов — воспроизведено минимальным примером вне проекта
(каталог с двумя файлами, `goose.Up` → паника в `sortAndConnectMigrations`).

## 2. Принятое решение

**Один файл на версию с аннотациями `-- +goose Up` / `-- +goose Down`**
(`internal/verdict/store/migrations/0001_stage1.sql`). Паника исчезает, down
сохраняется, тест up → down → up (п. 16.9) работает.

Косвенная находка: без аннотации `-- +goose Up` парсер отклоняет файл с
«unexpected state 0» — файлы должны начинаться с аннотации.

## 3. Альтернативы

- Пара .up.sql/.down.sql + игнор паники — невозможно: паника внутри goose.
- Форк/замена goose (напр., собственный раннер) — отклонено: ADR-0006 фиксирует
  goose, форк — лишняя поддержка.
- Пин на другую версию goose — проверено: поведение идентично в v3.24.2/v3.29.0.
