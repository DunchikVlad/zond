# ADR-impl: инкремент 5г — веб-UI и scheduler

Дата: 2026-10-20
Статус: accepted
Связь: blueprint п. 11.3 (ADR-0007), п. 15, п. 15.4; прогресс —
`2026-10-20-stage-5g-web-ui-scheduler.md`

## D1. UI работает поверх того же слоя store, что REST API — не через loopback-вызовы к собственному API

**Выбор:** обработчики `internal/web` вызывают store/дрейф/runner напрямую —
тот же слой данных и та же бизнес-логика, что у REST-обработчиков
(ApplyReview, ListVerdictsFiltered и т.д.).

**Отклонённая альтернатива:** in-process HTTP-клиент к собственному
`/api/v1/*` (буквальное чтение ADR-0007 «UI потребляет тот же REST API»).
В single-instance (ADR-0014) это лишний хоп через сетевой стек и точка
отказа (UI зависит от живости API-роутинга), а дублирования логики нет и
при прямом доступе — оба слоя вызывают одни методы store. Контракт данных
один, что и требует blueprint. Если появится отдельный SPA/внешний фронт —
он пойдёт по REST как положено.

## D2. Evidence-рендер whitelist'ом

Карточка ревью выводит только известные ключи evidence (`rules`, `sample`,
`llm_cache`, `reason`, `budget_exceeded`, `cluster_propagated`) в
контролируемом формате; неизвестные ключи молча пропускаются. Тестовый
контракт: строка под неизвестным ключом не появляется в HTML. Дополняет
ADR-0010 страховкой на случай появления в evidence новых полей с
нежелательной чувствительностью.

## D3. Retention audit_log не автоматизируется в продукте

П. 15.4 требует ≥180 дней «архив + проверка hash-chain». Автоудаление из
append-only журнала противоречило бы его назначению (подмена/удаление
детектируются цепочкой). Реализованы: автопрочистка сканов/вердиктов/
вызовов (>90 дней) и кэша (TTL). Для audit_log архив — операционная
процедура (внешний sink/WORM, этап 7), автоматика только после появления
sink (иначе «архив» = удаление).

## D4. CSP без 'unsafe-inline'; shortcuts и графики отложены

`default-src 'self'` закрывает inline script/style, что ломает привычные
UX-фичи (inline-обработчики клавиатурных shortcuts, style-атрибуты
прогресс-баров). Решение: фичи реализованы без inline-кода (progress —
текст/таблица), shortcuts — отдельным JS-файлом в доработку вместе с
политикой script-src. Trade-off: чуть проще UI сейчас в обмен на строгий
CSP из коробки (п. 14).

## D5. Bulk-ревью — последовательные транзакции без общего отката

Каждая карточка — своя транзакция ApplyReview (идемпотентна); сводка в
ответе. Общая транзакция на сотни карточек — длинная блокировка
единственного писателя SQLite; частичный успесс — легитимен (оператор
видит сводку и повторяет для отказавших).

## D6. Scheduler — robfig/cron/v3 в процессе serve

П. 15 (встроенный шедулер) при single-instance (ADR-0014): cron в процессе
serve, флаг `-scheduler=false` для отладки. Невалидное выражение источника
не роняет старт (warn+аудит) — отказ одного расписания не должен лишать
контур остальных задач (purge/retention).
