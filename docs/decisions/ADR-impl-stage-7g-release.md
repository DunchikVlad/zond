# ADR-impl: инкремент 7г — релиз v0.1: security-гейт, релизный pipeline, smoke-контур

Дата: 2026-10-23
Статус: accepted (с явным исключением: тег v0.1 — после прогона smoke)
Связь: blueprint п. 14 (security), п. 15 (деплой/харденинг), п. 16.7
(CI-ворота), п. 22 (DoD), п. 13.2; прогресс —
`docs/progress/2026-10-23-stage-7g-release.md`

## D1. Уязвимости закрываются бампом, а не подавлением

**Выбор:** три находки govulncheck в reachable-коде закрыты поднятием
версий: goxmldsig v1.6.0 (подпись SAML, GO-2026-4753), go-jose/v4 v4.1.4
(GO-2026-4945), toolchain go1.27.3 (crypto/x509, GO-2026-6809; go.mod
`go 1.27.3`).

**Отклонённая альтернатива:** `--show verbose`/игнор-листы govulncheck —
ложная зелень релизного гейта.

## D2. AttemptLimiter — в памяти, по IP, константы Defaults

**Выбор:** rate-limit неудачных входов (п. 14) — `auth.AttemptLimiter`:
скользящее окно неудач по ключу (IP клиента из RemoteAddr), блокировка
по достижении maxFails; константы Defaults (5/10 мин/15 мин), serve
собирает лимитер явно. Внешняя конфигурация — отложена («настраивается»
п. 14 трактуем как точку расширения).

**Обоснование:** single-instance-процесс (п. 15.1) — внешнее хранилище
счётчиков избыточно; IP — единственный устойчивый идентификатор без
прокси-парсинга (за reverse-proxy п. 15 ограничивает на hop'е).

## D3. Redactor: паттерны + явные env-значения, обёртка slog-handler'а

**Выбор:** `logging.SecretRedactor` маскирует структурные паттерны
(учётные данные в DSN/URI, Authorization/Bearer/Basic, X-Admin-Token) и
явные значения (env по конфигу + эвристика имён PASS/PWD/SECRET/TOKEN/KEY,
≥6 символов). Применение — обёртка slog.Handler: message и строковые
атрибуты до сериализации JSON.

**Отклонённая альтернатива:** маскирование только по списку env — не
ловит DSN с интерполированным паролем в ошибках драйвера; только паттерны
— не ловит произвольные значения ключей.

## D4. CSRF — double-submit, а не synchronizer token

**Выбор:** cookie `zond_csrf` (32 байта rand, не HttpOnly) + заголовок
`X-CSRF-Token` на мутациях; htmx добавляет заголовок через
`htmx:configRequest` из cookie. Расхождение → 403.

**Обоснование:** stateless (в памяти процесса ничего не хранится), не
требует встраивания токена в каждую форму server-rendered UI; в связке с
SameSite=Lax даёт два независимых слоя. Сynchronizer-token потребовал бы
сессионного хранилища токенов и правки всех форм — избыточно для
single-instance.

## D5. Авторитетный релиз — GitHub Actions на тег; Makefile — ручной режим

**Выбор:** release.yml (тег `v*`): матрица кросс-сборки → SHA256SUMS →
SBOM (syft) → cosign keyless (OIDC) → GitHub Release. Makefile `release`
повторяет набор локально; syft/cosign без инструмента — честный skip с
указанием CI-замены.

**Обоснование:** три обязательных артефакта п. 15 (checksums, SBOM,
подпись) должны собираться в контролируемой среде CI с OIDC-подписью, а
не на рабочей станции мейнтейнера.

## D6. Smoke-контур: один образ, общий том БД, healthcheck-гейтинг

**Выбор:** `deploy/docker-compose.yml`: app и smoke-scan — один и тот же
образ (zond:smoke), БД одна на контур; smoke-scan (`--profile smoke`)
ждёт healthcheck'и БД, пишет вердикты в общий том `zond-data`; UI поднимается
после и видит их. Порты наружу — только app на loopback.

**Обоснование:** «скан дошёл до done и вердикты видны в UI» (DoD) — один
связный контур без копирования БД; healthcheck-гейтинг убирает гонки
запуска без shell-скриптов.

## D7. Тег v0.1 — только после прогона smoke на docker-хосте

**Выбор:** при отсутствии docker в среде разработки тег не ставится:
pipeline release.yml готов, smoke-контур собран, но «эталонный контур
DoD зелёный» не подтверждён прогоном. Тег — следующим шагом на машине с
docker (`make smoke` → `git tag v0.1` → push тега).

**Обоснование:** «не представляй непроверенное как готовое»: тег
запускает релизный pipeline и создаёт релизные артефакты — это
точка невозврата.
