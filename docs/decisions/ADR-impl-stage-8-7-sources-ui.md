# ADR-impl: инкремент 8-7 — управление источниками и расписаниями из UI

Дата: 2026-10-25
Статус: accepted
Связь: ADR-0009 (connections.yaml — источник правды), ADR-0014
(hot-reload детекторов — вне скоупа), blueprint п. 11.3 (RBAC), п. 12
(секреты через ENV), п. 13.2/15 (расписания/окна); прогресс —
`docs/progress/2026-10-25-stage-8-7-sources-ui.md`

## D1. UI редактирует файл через yaml.Node, а не хранит источники в БД

**Выбор:** /sources правит connections.yaml через config.SourceEditor
(Node-дерево: комментарии и `${ENV}`-литералы сохраняются); файл остаётся
источником правды (ADR-0009).

**Отклонённая альтернатива:** таблица sources в SQLite с UI-CRUD — второй
источник правды, дрейф с файлом при ручных правках, миграции ради
конфигурации.

**Обоснование:** single source of truth дешевле; конфиг остаётся
версионируемым и ревьюируемым; секреты физически не попадают в Verdict
Store. Цена — аккуратность round-trip (решается Node-правкой).

## D2. Node-правка вместо round-trip через структуру

**Выбор:** мутации mapping-нод sources в yaml.v3-документе; сериализация
того же дерева.

**Отклонённая альтернатива:** LoadConnections → правка struct →
yaml.Marshal: раскрытые ENV-подстановки улетели бы в файл открытым
текстом — недопустимо.

**Обоснование:** безопасность по построению: в файл уходит только то, что
было в файле (плюс новые литералы). Побочка: inline-комментарий
редактируемой строки теряется — принято, зафиксировано тестом.

## D3. Горячий reload ограничен sources; детекторы — по-прежнему рестарт

**Выбор:** после записи файла serve перечитывает connections
(LoadConnections), меняет atomic.Pointer, scheduler.ReplaceSources
пересобирает cron. detectors.yaml/taxonomy.yaml не входят в reload.

**Обоснование:** запрос эксплуатации — источники и расписания; детекторы
меняются редко и трогают LLM-контур (промпты, кэш-ключи) — там нужна
осторожность ADR-0014 как отдельный инкремент. Атомарный провайдер
покрывает web-форму запуска, drift и runner.Start.

## D4. Пароль в dsn/uri — только ${ENV} (fail-closed)

**Выбор:** checkSecretRef отклоняет сохранение, если password в userinfo
не является `${...}`-ссылкой.

**Отклонённая альтернатива:** принимать с предупреждением — уступка
удобству против п. 12.

**Обоснование:** fail-closed (ADR-security-llm-isolation); файл с открытым
паролем — классическая утечка через репозиторий/бэкапы. net/url отклоняет
${} в userinfo — парсинг вручную, тесты на обеих СУБД.

## D5. Классические формы + csrf_token-поле вместо полного HTMX

**Выбор:** save/delete — обычные формы с hidden csrf_token (расширение
double-submit из S8-6); «Проверить» — htmx-фрагмент (результат без
навигации).

**Обоснование:** после S8-6 формы первоклассны; redirect после save —
простая и предсказуемая модель (PRG), нет состояния на клиенте. HTMX там,
где он даёт выигрыш (фрагмент результата пинга).
