# Решение: нейминг Zond и стартовые допущения scaffold (S0)

Статус: accepted
Дата: 2026-10-18
Автор: Coordinator / Stage 0

## 1. Контекст

Проект получил имя Zond (папка, GitHub-репозиторий `DunchikVlad/zond`), но blueprint
и architecture продолжают называть рабочий артефакт `classifier` (blueprint п. 3:
«переименование — механическая замена»). Кроме того, в ходе этапа 0 возникли
технические допущения, требующие фиксации.

## 2. Принятые решения

### 2.1 Module path и бинарник

- Go-модуль: `github.com/DunchikVlad/zond`; точка входа `cmd/zond`; бинарник `zond`.
- Blueprint/architecture **не переименованы** в этом чанке: по п. 25 blueprint
  изменения идут через PR с записью в Changelog — переименование артефакта будет
  отдельным документальным чанком до этапа 1.
- До тех пор допустимо расхождение: код/модуль — `zond`, документы — `classifier`.
  Источник правды по именованию артефакта сборки — код.

### 2.2 Интерполяция ${ENV} — после парсинга

Интерполяция выполняется рекурсивным обходом строковых полей уже распарсенной
структуры, а не сырых байт файла. Причина: интерполяция сырого текста ломается
на `${VAR}` в YAML-комментариях (реальный дефект, пойман проверкой конфига).
Fail-fast сохранён: все незаданные переменные собираются и перечисляются в ошибке.

### 2.3 configs/ci.env — фиктивные значения в репозитории

Для `make config-check` и CI в репозитории лежит `configs/ci.env` со значениями
`ci-dummy`/`test`. Допущение: файл не содержит секретов и не может быть использован
для доступа ни к чему реальному; реальные значения — только локально/в CI-secrets
(blueprint п. 12). Альтернатива (генерировать ENV на лету в каждой проверке) отклонена
как дублирование списка переменных.

### 2.4 Race-детектор локально требует cgo

На Windows `go test -race` требует `CGO_ENABLED=1` и gcc (mingw 16.2, scoop).
Зафиксировано: локальный прогон — `export PATH=...mingw/current/bin; CGO_ENABLED=1
go test -race ./internal/...`; в CI (ubuntu) race работает без cgo-настроек.

## 3. Отклонённые альтернативы

- Интерполяция до парсинга с предварительной «очисткой комментариев» — хрупкая
  обработка строк/экранирования в YAML.
- Переименование blueprint в том же чанке — нарушило бы регламент п. 25 (PR + Changelog)
  и смешало бы технический scaffold с документальным изменением.

## 4. Последствия

- Этап 1 начинается на модуле `github.com/DunchikVlad/zond`; импорты новых пакетов — от него.
- Перед этапом 1 нужен мелкий документальный чанк: переименование `classifier` → `zond`
  в blueprint/architecture с записью в Changelog (п. 25).
