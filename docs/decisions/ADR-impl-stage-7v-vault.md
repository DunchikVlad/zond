# ADR-impl: инкремент 7в — Vault: резолвер секретов (ADR-0012)

Дата: 2026-10-23
Статус: accepted
Связь: ADR-0012, blueprint п. 12.1 (секреты без хранения на сервере),
п. 14.1/14.2 (redact, аудит), R11 (недоступность Vault), п. 15.3
(doctor); преемник S7а (заглушка `vault SKIP` снята);
прогресс — `docs/progress/2026-10-23-stage-7v-vault.md`

## D1. Dynamic-секреты собираются через dsn_template

**Выбор:** запись `vault.secrets` с `path: database/creds/...` читает
`username`/`password` из лизы и подставляет в `dsn_template`
(`{{username}}`, `{{password}}` — оба плейсхолдера обязательны,
проверяется конфигурацией). Запись с `key` (kv-v2) возвращает значение
ключа как готовый DSN/URI. Поля `key` и `dsn_template`
взаимоисключающи.

**Контекст:** blueprint п. 12.1 показывает dynamic-путь
(`database/creds/ch-prod-readonly`), но не специфицирует, как из пары
username/password получить полный DSN: хост/порт/БД — не секреты и не
должны жить в Vault.

**Отклонённая альтернатива:** DSN-шаблон в `sources` рядом с `ref` —
дублирование адресации и соблазн вернуть `dsn` со встроенными
учётными данными.

## D2. Кэш — только для dynamic-лиз; kv-v2 дочитывается всегда

**Выбор:** закэшированы только динамические лизы (до `expiresAt`,
продление фоновой горутиной в середине срока). kv-v2 читается из Vault
на каждое установление коннекта, кэша нет.

**Обоснование:** у dynamic-лиз срок жизни определён протоколом, и кэш —
это требование R11 (деградация при недоступности Vault до истечения
лизы). kv-v2 ротируется оператором записью нового значения; кэш скрыл бы
ротацию на неопределённый срок. Чтение на коннект — дёшево: коннектор
открывается на скан, не на каждую таблицу.

## D3. Продление лиз: 403 — отзыв, иное — кэш до истечения

**Выбор:** renew (`sys/renew/<lease_id>`, increment = полный срок)
в середине текущего срока. Ошибка 403 трактуется как отзыв лизы: кэш
сбрасывается немедленно, renewer завершается, событие
`lease_revoked` в аудит. Иная ошибка (сеть, 5xx): renewer завершается,
кэш живёт до `expiresAt`, событие `renew_failed` в аудит; следующий
`Resolve` за пределами срока прозрачно читает новую лизу.

**Обоснование:** fail-closed там, где кэш заведомо невалиден (отзыв), и
fail-safe там, где валидность определяется сервером (срок не изменился
при сбое сети). Это и есть «прозрачный реконнект с новым секретом без
перезапуска» п. 12.1 — на границе коннектов, без вмешательства в
коннекторы (реконнект внутри длительного скана — отдельная задача,
вне скоупа: коннектор открывается на скан).

## D4. Аудит: факт без значений; actor — из контекста/scheduler

**Выбор:** `AuditHook(ctx, ref, path, action)` с действиями `resolve`,
`lease_renew`, `lease_revoked`, `renew_failed`. Значения секретов в
аудит не попадают никогда (п. 14.2) — только ref и path. Actor:
`resolve` — инициатор скана через значение в контексте (cli/sso/
token/scheduler по каналу запуска), события продления — всегда
`scheduler` (п. 14.2: фоновые задачи). Ошибка записи аудита — warn в
лог, скан не роняется.

**Особый случай doctor:** аудит отключён (`hook=nil`) — doctor
read-only preflight (п. 15.3), его чтения секретов не должны порождать
события инцидент-реагирования.

## D5. Аутентификация: token из env (dev) | kubernetes login (prod)

**Выбор:** `auth.method: token` — токен читается из env-переменной,
имя которой задано в `auth.token_env` (не задана переменная —
fail-fast на старте). `auth.method: kubernetes` — JWT читается из файла
(`auth.jwt_file`, по умолчанию стандартный путь сервис-аккаунта) и
меняется на клиентский токен через `auth/kubernetes/login` с
`auth.role`. Токен в конфиге невозможен: строгая схема (ADR-0009)
отвергает неизвестный ключ `token`.

## D6. Зависимость hashicorp/vault/api и границы depguard

**Выбор:** `github.com/hashicorp/vault/api v1.16.0`; транспортный
таймаут 10 с; `SetMaxRetries(0)` — без библиотечных ретраев (fail-fast,
прецедент webhook S6в: при сомнении — отказ, ретрай — на уровне
следующего коннекта/прогона по расписанию). Пакет `internal/secrets`
не импортирует `net/http` (depguard-граница architecture.md п. 3
сохранена; 403 определяется по `api.ResponseError.StatusCode`).

**Отклонённая альтернатива:** raw HTTP-клиент на stdlib — дублирование
разбора ответов Vault (kv-v2 unwrap, lease-поля, ошибки) при наличии
первой партии blueprint-зависимостей.

## D7. doctor: vault — аутентификация, vault.read — чтение записей

**Выбор:** код `vault` — конструирование резолвера (аутентификация):
выключен → SKIP, offline → SKIP, fail → FAIL. Код `vault.read` (по
строке на запись `vault.secrets`) — реальное чтение: доказывает
доступность Vault, политику токена и корректность path/key/template.
Резолвер закрывается по завершении прогона (`defer Close` в `Run`) —
renewer'ы лиз не живут дальше doctor. Источники с `ref`: offline →
`source.open SKIP`, отсутствие резолвера (auth-фейл) → FAIL со ссылкой
на проверку vault, сбой резолва → FAIL.

**Обоснование:** проверка без проверяемого компонента — ложная
уверенность (прецедент D5 S7а); «прочитался ли конкретный секрет» —
единственная честная online-проверка.

## D8. Смешанный контур и двусторонняя ссылочная целостность

**Выбор:** при включённом Vault часть источников может оставаться на
`dsn`/`uri` (ENV), часть — на `ref`: адресующее поле одно на источник
(`dsn|uri|ref`). Каждый `ref` источника обязан иметь запись
`vault.secrets` и наоборот (dangling-запись — ошибка конфигурации).

**Обоснование:** постепенная миграция контура на Vault без большого
взрыва; двусторонняя проверка ловит опечатки в `ref` (типичная
конфигурационная ошибка) в момент `config validate`, а не на коннекте.
