# ADR-impl: инкремент 7а — preflight doctor

Дата: 2026-10-22
Статус: accepted
Связь: blueprint п. 15.3 (preflight), п. 10.1/10.7 (изоляция/egress LLM),
п. 14.2 (hash-chain аудита); прецедент `agent-check` (этап 4);
прогресс — `docs/progress/2026-10-22-stage-7a-doctor.md`

## D1. Один пакет internal/doctor, таблица кодов, режимы online/offline

**Выбор:** проверки собраны в пакете doctor с отчётом из строк
{code, subject, status OK/FAIL/WARN/SKIP, detail}; сетевые проверки
(Ping источников, DNS, пробный вызов) — только с Options.Online
(CLI `-online`; `serve -strict` всегда online), иначе строки SKIP.

**Обоснование:** п. 15.3 требует и таблицу с кодами, и блокировку serve.
Единый пакет даёт оба потребителя (CLI и strict) без дублирования; режимы
делают doctor пригодным для CI (offline: конфиг/env/egress/диск/цепочка —
детерминированно, без сети) и для pre-prod (online). FAIL — единственный
блокирующий статус; WARN зарезервирован (пока не используется).

## D2. Egress-валидация прокси и без -online

**Выбор:** `agent.egress` строит прокси агента (конструктор валидирует
endpoint по egress-политике, включая DNS-резолв, fail-closed) и в
offline-режиме; фейковый/не резолвящийся endpoint = FAIL уже без `-online`.

**Контекст:** прецедент — `agent-check` (этап 4) делает так же и
документирует это.

**Обоснование:** опечатка в endpoint — конфигурационная ошибка, не
сетевая; ждать `-online`, чтобы её увидеть, значит пропустить её в CI.
П. 10.7 fail-closed: запрещённый endpoint не должен проходить ни в каком
режиме. Пробный вызов (agent.probe) — отдельная online-проверка формата
ответа.

## D3. Диск: build-tags вместо единой абстракции

**Выбор:** `freeSpace(path)` — две реализации с build-tags:
`doctor_disk_unix.go` (!windows, `syscall.Statfs`, stdlib) и
`doctor_disk_windows.go` (`GetDiskFreeSpaceExW` через `x/sys/windows`,
которая стала прямой зависимостью go.mod).

**Отклонённая альтернатива:** единая реализация через x/sys/unix+x/sys/windows —
потянула бы x/sys/unix на все платформы (лишнее для linux-only деплоя).

**Обоснование:** минимум зависимостей на POSIX (stdlib), корректный
Windows-путь; кросс-сборка linux/amd64|arm64 + windows проверена (п. 18
требует обе платформы).

## D4. Независимые проверки не отключаются чужой поломкой

**Выбор:** конфиг не загрузился (nil Bundle) → FAIL config.load, но
disk.space и audit.chain выполняются; ошибка одной проверки не прерывает
остальные.

**Обоснование:** preflight ценен полным списком проблем, а не первой из
них; оператор чинит всё за один проход. Отчёт — единый артефакт для
runbook'ов.

## D5. Проверки Vault и backup — не в S7а

**Выбор:** vault — SKIP «не реализован (S7в)»; backup не проверяется.

**Обоснование:** проверка без проверяемого компонента — ложная уверенность;
закроются своими инкрементами этапа 7 (ADR-0012, п. 15.2).
